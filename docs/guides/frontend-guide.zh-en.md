# Frontend Guide (中文 + English)

导航 / Navigation: [返回项目首页](../../README.md) | [文档首页](../README.md) | [测试手册](testing-playbook.zh-en.md)

## 1) 前端目标 / Frontend Scope

中文：
前端工作台基于 Vue 3 + View UI Plus，提供登录、项目管理、项目详情、资源管理、Provider Connection、Workbench 会话调试、Workflow 测试和 My Files 文件管理。

English:
The frontend workbench is built with Vue 3 + View UI Plus and provides login, project management, project details, resource management, Provider Connections, Workbench chat debugging, Workflow testing, and My Files management.

## 2) 页面结构 / Pages

1. Login
- 注册 / 登录，获取 Bearer token 并保存会话。 / Register or log in, receive a Bearer token, and persist the session.

2. Dashboard
- 展示当前登录用户、平台结构摘要与系统状态。 / Show the current user, platform summary, and system status.

3. Projects
- 创建、编辑、删除项目。 / Create, edit, and delete projects.
- 按项目 ID 或项目名过滤。 / Filter by project ID or name.
- 点击项目名进入详情页。 / Click a project name to open its detail page.
- 管理成员（添加 / 删除）和 member manager 授权。 / Manage members, including add/remove and member-manager delegation.

4. Project Detail
- 查看项目基础信息。 / View basic project information.
- 列出该项目资源。 / List resources in the project.
- 按资源 ID 或资源名过滤。 / Filter by resource ID or name.

5. Resources
- 按类型维护资源（agent/workflow/tool/skill/mcp/knowledge_base）。 / Manage resources by type: agent, workflow, tool, skill, MCP, and knowledge_base.
- 支持默认资源模板、我的资源列表、创建、编辑、删除。 / Supports default templates, owned-resource lists, create, edit, and delete.
- Agent 创建/编辑支持 Env profile 与 URL + API Key 两种 provider 配置方式。 / Agent create/edit supports Env profile and URL + API Key provider configuration modes.
- Tool 支持代码和输入/输出 schema。 / Tools support code plus input/output schemas.
- Skill 支持上传 zip 或文件夹、查看 SKILL.md、测试和绑定关系管理。 / Skills support zip/folder upload, SKILL.md preview, testing, and binding management.
- Knowledge 支持文档上传、分页、删除和 reprocess。 / Knowledge supports document upload, pagination, deletion, and reprocessing.
- MCP 创建/编辑支持 Quick Test 和保存后的行级 Test。 / MCP create/edit supports Quick Test and row-level Test after saving.
- Workflow 创建/编辑支持图形化 Canvas、分支、汇合节点和 JSON 同步。 / Workflow create/edit supports visual Canvas, branches, join nodes, and JSON synchronization.

6. Workbench
- 先选择项目（支持按项目名/ID过滤）。 / Select a project first, with project name/ID filtering.
- 加载当前项目 Agent，下拉选择 agent_id。 / Load Agents in the current project and select an agent_id from the dropdown.
- 创建会话，加载项目下历史会话。 / Create sessions and load historical sessions in the project.
- 打开历史会话并查看消息。 / Open a historical session and view its messages.
- 查看 Runtime Run Timeline 与事件。 / View Runtime Run Timeline and events.
- 发送消息到 runtime。 / Send messages to the runtime.

7. Workflows
- 列出 workflow 资源。 / List workflow resources.
- 点击 Test 进入 Workflow Detail。 / Click Test to open Workflow Detail.
- 输入 JSON 任务并运行。 / Enter a JSON task and run it.
- 查看 Run History、最终输出和 Step Trace。 / View Run History, final output, and Step Trace.

8. My Files
- 上传用户文件或文件夹。 / Upload user files or folders.
- 搜索、分页、下载和删除文件。 / Search, paginate, download, and delete files.
- Skill/Agent/Workflow 生成的文件会保存到 generated 路径下。 / Files generated by Skills, Agents, or Workflows are saved under the generated path.

### Workbench 运行可观测性 / Runtime Observability in Workbench

1. 发送消息后，后端会创建 run 记录并返回 run_id。 / After sending a message, the backend creates a run record and returns `run_id`.
2. Workbench 的 Run Timeline 列表显示每次运行状态：running/succeeded/failed。 / The Workbench Run Timeline shows each run status: running, succeeded, or failed.
3. 点击某个 run 的 Events 可以查看分阶段事件： / Click Events for a run to inspect staged events:
- runtime: 执行开始/完成/失败
- agent: 选中的 agent 与模型信息
- code/tool/mcp: code-mode Agent 执行、Tool 调用与 MCP 调用信息
4. 后续接入更多事件时，前端时间线可按事件 stage 扩展显示。 / As more events are added, the frontend timeline can expand by event stage.

## 6) Typical Flow

1. 登录或注册。 / Log in or register.
2. 在 Projects 创建项目。 / Create a project in Projects.
3. 点项目名进入 Project Detail 查看资源。 / Click the project name to open Project Detail and view resources.
4. 在 Resources 页面创建 Agent，并按需绑定 Tool、Skill、MCP 或 Knowledge。 / Create an Agent in Resources and bind Tools, Skills, MCPs, or Knowledge as needed.
5. 如需自定义模型连接，在 Agent 表单中使用 URL + API Key 加载模型并测试。 / For custom model connections, use URL + API Key in the Agent form to load models and test.
6. 在 Workbench 选择项目并加载 Agent。 / Select a project in Workbench and load Agents.
7. 创建会话并发送消息。 / Create a session and send a message.
8. 在 Run Timeline 中查看 run 与 events。 / Inspect runs and events in Run Timeline.
9. 如需多 Agent 编排，在 Workflows 创建流程并进入 Test 页面运行。 / For multi-Agent orchestration, create a flow in Workflows and run it from the Test page.

## 7) Acceptance Checklist

1. 登录后可正常进入 Dashboard，刷新页面不丢失会话。
2. Projects 支持按名称/ID过滤并可进入详情。
3. Project Detail 可查看资源并按名称/ID过滤。
4. Resources 可创建、编辑、删除资源，并可测试 Agent/MCP/Skill/Workflow。
5. Workbench 可选择项目、选择 Agent、创建会话、发送消息。
6. Workbench 可看到 run 列表与事件 timeline。
7. Workflow Detail 可运行流程、查看历史和 Step Trace。
8. My Files 可上传、搜索、分页、下载和删除文件。
9. 所有 API 请求都带 Bearer token。

## 8) Troubleshooting

- 登录失败（401）：检查账号密码，确认后端 auth 路由已加载。
- 项目无权限（403）：当前用户不在项目成员内。
- Workbench 无会话：先在当前选中项目下创建 session。
- Workbench 无 Agent：确认项目下已创建 kind=agent 资源。
- Timeline 无数据：确认消息是通过 Workbench 发送且后端已执行最新迁移。
- Provider Connection 测试失败：检查 Base URL、API Key、模型名和网络连通性。
- MCP 测试失败：检查 endpoint_url、headers、timeout_seconds 和 MCP server 的 `/health`、`/tools`。
- 前端空白页：检查 VITE_API_BASE_URL 与后端端口是否一致。

- Workflow Test 一直 running：刷新 Run History，点击 completed/failed 记录查看是否前端状态未同步；同时检查后端 `/api/v1/workflows/{workflow_id}/runs/{run_id}`。
- My Files 删除失败：确认路径来自 `/api/v1/files/me`，不要手工拼接绝对路径。
